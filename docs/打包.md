# 打包指南

本文说明如何将 **Instant Share** 从源码构建为可分发的桌面应用。  
当前桌面端采用 **Go c-shared 动态库 + dart:ffi 进程内运行** 方案，打包前必须先编译对应平台的原生库。

---

## 一、打包前必读

### 1.1 产物链路

```
instant_share_server/cmd/lib   ──build_lib──▶   assets/lib/*.dylib|.dll|.so
                                                      │
Flutter 构建 ─────────────────────────────────────────┘
       │
       ▼
  平台安装包 / 可运行目录（库随 App 一起分发）
```

| 平台 | 原生库产物 | 打包时落地位置 | 加载方式 |
|---|---|---|---|
| macOS | `libinstantshare.dylib` | `.app/Contents/Resources/` | `embedded_server_library_locator.dart` |
| Windows | `instantshare.dll` | 与 `instant_share.exe` 同目录 | 同上 |
| Linux | `libinstantshare.so` | 与可执行文件同目录（CMake 待补） | 同上 |

> **改了 Go 代码必须重新跑 `build_lib`，再执行 `flutter build`。**

### 1.2 环境要求

| 工具 | 版本 / 说明 |
|---|---|
| Flutter SDK | `>=3.9.0` |
| Go | `>=1.25`，且 `CGO_ENABLED=1` |
| macOS 打包 | Xcode、Command Line Tools |
| Windows 打包 | Visual Studio 2022（含「使用 C++ 的桌面开发」）、Go、MinGW/gcc |
| Linux 打包 | `clang`、`cmake`、`ninja-build` 等 Flutter Linux 依赖 |

## 二、第一步：构建 Go 内嵌库（各平台通用前置）

在项目根目录执行，**目标平台在哪台机器打就在哪台机器编库**（Windows DLL 建议在 Windows 上编）。

### macOS（通用库 arm64 + x86_64）

```bash
cd instant_share_server
./build_lib.sh macos
```

产物：`assets/lib/libinstantshare.dylib`（约 18MB，已 lipo + ad-hoc 签名）

### Windows（amd64）

```bat
cd instant_share_server
build_lib.bat
```

产物：`assets/lib/instantshare.dll`

macOS 上交叉编译（需 `brew install mingw-w64`）：

```bash
cd instant_share_server
./build_lib.sh windows
```

### Linux（amd64）

```bash
cd instant_share_server
./build_lib.sh linux
```

产物：`assets/lib/libinstantshare.so`

---

## 三、第二步：Flutter 依赖与资源

```bash
# 项目根目录
flutter pub get
```

macOS 会把 `libinstantshare.dylib` 打进 Flutter assets（`pubspec.yaml` 已声明）。  
Windows / Linux 的库**不**走 pubspec，由 CMake 从 `assets/lib/` 拷贝到输出目录。

若修改了文案，先更新翻译再打包：

```bash
./asloc.sh
```

## 四、各平台 Release 打包

### 4.1 macOS

**1. 构建 Release**

```bash
cd instant_share_server && ./build_lib.sh macos && cd ..
flutter build macos --release
```

**2. 输出位置**

```
build/macos/Build/Products/Release/instant_share.app
```

**3. 库如何进包**

Xcode 构建阶段 `Copy Share Server`（`macos/copy_share_server.sh`）会把：

- `assets/lib/libinstantshare.dylib` → `instant_share.app/Contents/Resources/`

**4. 验证**

```bash
# 库是否在 bundle 内
ls build/macos/Build/Products/Release/instant_share.app/Contents/Resources/libinstantshare.dylib

# 直接运行
open build/macos/Build/Products/Release/instant_share.app
```

App 启动后应能访问 `http://127.0.0.1:8080/api/v1/server/health`。

**5. 对外分发（可选）**

- **压缩分发**：将 `.app` 打成 zip 即可。
- **公证 / 签名**：对外公开发布需 Apple Developer 证书，对 `.app` 及内嵌 dylib 做正式 codesign + notarize（当前脚本仅 ad-hoc 签名，适合内测）。
- **DMG**：可用 `create-dmg` 等工具制作安装镜像。

---

### 4.2 Windows

**1. 构建 Release**

```bat
cd instant_share_server
build_lib.bat
cd ..
flutter build windows --release
```

**2. 输出位置**

```
build\windows\x64\runner\Release\
├── instant_share.exe
├── instantshare.dll      ← CMake 自动拷贝
├── flutter_windows.dll
├── data\
└── ...（插件依赖 dll）
```

**3. 库如何进包**

`windows/CMakeLists.txt` 在 install 阶段把 `assets/lib/instantshare.dll` 拷到 exe 同目录。  
若构建日志出现 `instantshare.dll not found`，说明未执行 `build_lib.bat`。

**4. 验证**

```bat
cd build\windows\x64\runner\Release
instant_share.exe
```

**5. 对外分发**

将整个 `Release` 目录打包为 zip，或使用 [Inno Setup](https://jrsoftware.org/isinfo.php) / [NSIS](https://nsis.sourceforge.io/) 制作安装程序。  
分发时务必包含 `instantshare.dll`，与 exe 保持同目录。

---

### 4.3 Linux

**1. 构建 Release**

```bash
cd instant_share_server && ./build_lib.sh linux && cd ..
flutter build linux --release
```

**2. 输出位置**

```
build/linux/x64/release/bundle/
├── instant_share          # 可执行文件
├── lib/                   # Flutter 引擎等
└── data/
```

**3. 注意事项**

Linux 端 CMake **尚未**像 Windows 一样自动拷贝 `libinstantshare.so`。Release 前需手动复制：

```bash
cp assets/lib/libinstantshare.so build/linux/x64/release/bundle/
chmod +x build/linux/x64/release/bundle/instant_share
```

**4. 验证**

```bash
cd build/linux/x64/release/bundle
./instant_share
```

**5. 对外分发**

将整个 `bundle/` 目录打成 `tar.gz`，或制作 `.deb` / AppImage（按需选型）。

## 五、Debug 与日常开发

开发时不必每次打 Release，直接：

```bash
# macOS
cd instant_share_server && ./build_lib.sh macos && cd ..
flutter run -d macos

# Windows
cd instant_share_server && build_lib.bat && cd ..
flutter run -d windows
```

调试时可跳过打包路径，直接指定库：

```bash
# macOS / Linux
export INSTANT_SHARE_SERVER_LIB=/绝对路径/libinstantshare.dylib

# Windows
set INSTANT_SHARE_SERVER_LIB=C:\path\to\instantshare.dll
```

## 六、打包检查清单

发布前逐项确认：

- [ ] Go 源码有变更 → 已重新执行对应平台 `build_lib`
- [ ] `assets/lib/` 下存在当前平台的库文件
- [ ] `flutter build <platform> --release` 无报错
- [ ] 安装包 / 输出目录内**包含**原生库（macOS: Resources 内 dylib；Windows: exe 旁 dll）
- [ ] 冷启动 App 后 `/api/v1/server/health` 返回 `ok: true`
- [ ] 分享流程（选文件 → 生成链接 → 接收端下载）正常
- [ ] 退出 App 后 8080 端口已释放（进程内模式无残留子进程）
- [ ] 版本号已更新（`pubspec.yaml` 的 `version:`）

## 七、常见问题

### Q: macOS 提示找不到 dylib / 服务启动失败

1. 确认已执行 `./build_lib.sh macos`
2. 完整构建：`flutter run -d macos`（不要仅热重载）
3. 检查：`instant_share.app/Contents/Resources/libinstantshare.dylib` 是否存在

### Q: Windows 提示找不到 instantshare.dll

1. 在 Windows 上执行 `instant_share_server\build_lib.bat`
2. 确认 `build\windows\x64\runner\Release\instantshare.dll` 与 exe 同目录
3. 或设置 `INSTANT_SHARE_SERVER_LIB` 指向 dll 绝对路径

### Q: 改了 Go 代码但行为没变

必须重新 `build_lib` 再 `flutter build` / `flutter run`，Flutter 热重载**不会**重新编译 Go 库。

### Q: build_lib 报 mingw / gcc 找不到（Windows 交叉编译）

- Windows：安装 [MSYS2](https://www.msys2.org/) 或 Go 安装包附带的 gcc
- macOS 交叉编 Windows：`brew install mingw-w64`

### Q: 8080 端口被占用

桌面端默认固定 8080。关闭占用进程或结束残留的 `instant-share-server`（历史子进程方案）。  
移动端后续可改为 `StartServer(0)` 动态端口。
