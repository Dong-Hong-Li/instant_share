# 打包指南

本文说明如何将 **Instant Share** 从源码构建为可分发的桌面 / 移动应用。

分享服务按平台采用不同运行时（由 `ShareServerHost` 分流）：


| 平台                      | 运行时                          | 构建物                                                       |
| ----------------------- | ---------------------------- | --------------------------------------------------------- |
| **Windows**             | 独立子进程 `ProcessServerRuntime` | `assets/bin/instant-share-server.exe`（**无需** MinGW / CGO） |
| macOS / Linux / Android | 进程内 c-shared + `dart:ffi`    | `assets/lib/*` 或 `jniLibs`（需 `CGO_ENABLED=1`）             |


---

## 一、打包前必读

### 1.1 产物链路

**Windows（推荐，当前默认）**

```
instant_share_server/cmd/server  ──go build──▶  assets/bin/instant-share-server.exe
                                                      │
Flutter 构建（CMake install）──────────────────────────┘
       │
       ▼
  与 instant_share.exe 同目录分发
```

**macOS / Linux / Android（进程内库）**

```
instant_share_server/cmd/lib   ──build_lib──▶   assets/lib/*.dylib|.so
                                                      │          └─ android jniLibs
Flutter 构建 ─────────────────────────────────────────┘
```


| 平台      | 构建产物                       | 打包时落地位置                    | 加载方式                                   |
| ------- | -------------------------- | -------------------------- | -------------------------------------- |
| Windows | `instant-share-server.exe` | 与 `instant_share.exe` 同目录  | `process_server_runtime.dart`          |
| macOS   | `libinstantshare.dylib`    | `.app/Contents/Resources/` | `embedded_server_library_locator.dart` |
| Linux   | `libinstantshare.so`       | 与可执行文件同目录（CMake 待补）        | 同上                                     |
| Android | `libinstantshare.so`       | `jniLibs/<abi>/`           | 同上                                     |


> **改了 Go 代码必须重新编译对应平台产物**，再执行 `flutter build` / `flutter run`。Flutter 热重载不会重编 Go。

可选：Windows 若已安装 MinGW/gcc，仍可用 `build_lib.bat` 生成 `instantshare.dll`；当前运行时默认走子进程，**不依赖**该 DLL。

### 1.2 环境要求


| 工具          | 版本 / 说明                                                     |
| ----------- | ----------------------------------------------------------- |
| Flutter SDK | `>=3.9.0`                                                   |
| Go          | `>=1.25`                                                    |
| Windows 打包  | Visual Studio（含「使用 C++ 的桌面开发」）+ Go；**不必**装 MinGW            |
| macOS 打包    | Xcode、Command Line Tools；编 dylib 时需 `CGO_ENABLED=1`         |
| Linux 打包    | `clang`、`cmake`、`ninja-build` 等 Flutter Linux 依赖；编 so 需 CGO |
| Android 打包  | Android NDK（`ANDROID_NDK_HOME` 或 `ANDROID_HOME`）            |

## 二、第一步：构建 Go 服务产物

在**目标平台机器**上编译（交叉编译仅作补充）。

### Windows（amd64，推荐）

无需 CGO / MinGW：

```bat
cd instant_share_server
go build -o ..\assets\bin\instant-share-server.exe .\cmd\server
```

产物：`assets/bin/instant-share-server.exe`

PowerShell 注意：本地脚本要用 `.\` 前缀，例如 `.\build_lib.bat`（编 DLL 时才需要）。

**可选（DLL，需 MinGW/gcc）**：

```bat
cd instant_share_server
.\build_lib.bat
```

产物：`assets/lib/instantshare.dll`。若报 `gcc not found`，说明未装 MinGW——请改用上方 `go build` 子进程方案。

### macOS（通用库 arm64 + x86_64）

```bash
cd instant_share_server
./build_lib.sh macos
```

产物：`assets/lib/libinstantshare.dylib`（约 18MB，已 lipo + ad-hoc 签名）

### Linux（amd64）

```bash
cd instant_share_server
./build_lib.sh linux
```

产物：`assets/lib/libinstantshare.so`

### Android（三 ABI）

见 [第八节](#八android-release-打包)。

---



## 三、第二步：Flutter 依赖与资源

```bash
# 项目根目录
flutter pub get
```

- macOS：`libinstantshare.dylib` 经 `pubspec.yaml` / Xcode 拷贝脚本进 bundle。
- Windows：`instant-share-server.exe` **不**走 pubspec；`windows/CMakeLists.txt` 从 `assets/bin/` 拷到 exe 同目录。
- Linux：库暂需手动拷贝（见 4.3）。

若修改了文案，先更新翻译再打包：

```bash
./asloc.sh
```

## 四、各平台 Release 打包



### 4.1 macOS

**1. 构建 Release**

```bash
cd instant_share_server && ./build_lib.sh macos && cd ..
flutter build macos --release
```

**2. 输出位置**

```
build/macos/Build/Products/Release/instant_share.app
```

**3. 库如何进包**

Xcode 构建阶段 `Copy Share Server`（`macos/copy_share_server.sh`）会把：

- `assets/lib/libinstantshare.dylib` → `instant_share.app/Contents/Resources/`

**4. 验证**

```bash
ls build/macos/Build/Products/Release/instant_share.app/Contents/Resources/libinstantshare.dylib
open build/macos/Build/Products/Release/instant_share.app
```

App 启动后应能访问健康检查接口（端口由系统分配，见日志 / 界面上的分享地址）。

**5. 对外分发（可选）**

- **压缩分发**：将 `.app` 打成 zip 即可。
- **公证 / 签名**：对外公开发布需 Apple Developer 证书，对 `.app` 及内嵌 dylib 做正式 codesign + notarize（当前脚本仅 ad-hoc 签名，适合内测）。
- **DMG**：可用 `create-dmg` 等工具制作安装镜像。

---



### 4.2 Windows

**1. 构建 Release**

```bat
cd instant_share_server
go build -o ..\assets\bin\instant-share-server.exe .\cmd\server
cd ..
flutter build windows --release
```

**2. 输出位置**

```
build\windows\x64\runner\Release\
├── instant_share.exe
├── instant-share-server.exe   ← CMake 从 assets/bin 拷贝（必需）
├── flutter_windows.dll
├── data\
└── ...（插件依赖 dll）
```

**3. 如何进包**

`windows/CMakeLists.txt` 在 install 阶段把 `assets/bin/instant-share-server.exe` 拷到 exe 同目录。  
若缺该文件，App 启动会报未找到独立服务二进制。

（可选）若本地有 `assets/lib/instantshare.dll`，CMake 也会一并拷贝，但当前运行时默认不加载它。

**4. 验证**

```bat
cd build\windows\x64\runner\Release
instant_share.exe
```

日志中应出现子进程相关输出，以及 `INSTANT_SHARE_READY port=...`（服务端）或 Flutter 侧 `[ShareServer] 子进程服务已启动`。

**5. 对外分发**

将整个 `Release` 目录打包为 zip，或使用 [Inno Setup](https://jrsoftware.org/isinfo.php) / [NSIS](https://nsis.sourceforge.io/) 制作安装程序。  
分发时务必包含 `instant-share-server.exe`，与 `instant_share.exe` 保持同目录。

---



### 4.3 Linux

**1. 构建 Release**

```bash
cd instant_share_server && ./build_lib.sh linux && cd ..
flutter build linux --release
```

**2. 输出位置**

```
build/linux/x64/release/bundle/
├── instant_share          # 可执行文件
├── lib/                   # Flutter 引擎等
└── data/
```

**3. 注意事项**

Linux 端 CMake **尚未**像 Windows 一样自动拷贝 `libinstantshare.so`。Release 前需手动复制：

```bash
cp assets/lib/libinstantshare.so build/linux/x64/release/bundle/
chmod +x build/linux/x64/release/bundle/instant_share
```

**4. 验证**

```bash
cd build/linux/x64/release/bundle
./instant_share
```

**5. 对外分发**

将整个 `bundle/` 目录打成 `tar.gz`，或制作 `.deb` / AppImage（按需选型）。

## 五、Debug 与日常开发

```bash
# macOS
cd instant_share_server && ./build_lib.sh macos && cd ..
flutter run -d macos

# Windows（推荐：子进程，无需 gcc）
cd instant_share_server
go build -o ..\assets\bin\instant-share-server.exe .\cmd\server
cd ..
flutter run -d windows

# Linux
cd instant_share_server && ./build_lib.sh linux && cd ..
flutter run -d linux
```

调试覆盖路径：

```bash
# macOS / Linux：指定 c-shared 库
export INSTANT_SHARE_SERVER_LIB=/绝对路径/libinstantshare.dylib

# Windows：指定独立服务 exe
set INSTANT_SHARE_SERVER_BIN=C:\path\to\instant-share-server.exe
```

## 六、打包检查清单

发布前逐项确认：

- [ ] Go 源码有变更 → 已重新编译对应平台产物（Windows：`go build ./cmd/server`；其它：`build_lib`）
- [ ] Windows：`assets/bin/instant-share-server.exe` 存在；macOS/Linux：`assets/lib/` 下有库文件
- [ ] `flutter build <platform> --release` 无报错
- [ ] 安装包 / 输出目录内包含服务二进制（Windows: exe 旁 `instant-share-server.exe`；macOS: Resources 内 dylib）
- [ ] 冷启动 App 后健康检查可用（`/api/v1/server/health` 返回 `ok: true`）
- [ ] 分享流程（选文件 / 文章 → 生成链接 → 接收端访问）正常
- [ ] 退出 App 后分享服务已关闭（Windows 子进程随父进程退出；其它为进程内）
- [ ] 版本号已更新（`pubspec.yaml` 的 `version:`）

## 七、常见问题



### Q: macOS 提示找不到 dylib / 服务启动失败

1. 确认已执行 `./build_lib.sh macos`
2. 完整构建：`flutter run -d macos`（不要仅热重载）
3. 检查：`instant_share.app/Contents/Resources/libinstantshare.dylib` 是否存在



### Q: Windows 提示找不到 instant-share-server / 服务启动失败

1. 执行：
  ```bat
   cd instant_share_server
   go build -o ..\assets\bin\instant-share-server.exe .\cmd\server
  ```
2. 确认 `build\windows\x64\runner\Debug`（或 `Release`）下有 `instant-share-server.exe`
3. 或设置 `INSTANT_SHARE_SERVER_BIN` 指向 exe 绝对路径
4. **不要**再依赖过时的 `instantshare.dll`（未装 MinGW 时 `build_lib.bat` 会失败，属预期）



### Q: `build_lib.bat` 报 `gcc not found`

Windows 编 DLL 需要 MinGW。当前默认方案**不需要** DLL，请改用：

```bat
go build -o ..\assets\bin\instant-share-server.exe .\cmd\server
```

若仍想编 DLL：安装 [MSYS2](https://www.msys2.org/) / WinLibs / LLVM-MinGW，将 `gcc` 加入 PATH 后再跑 `.\build_lib.bat`。

### Q: 改了 Go 代码但行为没变

必须重新编译 Go 产物后再 `flutter build` / `flutter run`。热重载不会更新原生库或子进程 exe。

### Q: 端口被占用 / 找不到 8080

桌面端已改为**系统分配端口**（`port=0`），不再固定 8080。以启动日志或界面上的分享地址为准。  
若曾使用旧版子进程，可手动结束残留的 `instant-share-server.exe`。

## 八、Android Release 打包



### 8.1 构建 Go 内嵌库（三 ABI）

需安装 Android NDK，并设置 `ANDROID_NDK_HOME` 或 `ANDROID_HOME`：

```bash
cd instant_share_server
./build_lib.sh android
```

产物：

```
android/app/src/main/jniLibs/arm64-v8a/libinstantshare.so
android/app/src/main/jniLibs/armeabi-v7a/libinstantshare.so
android/app/src/main/jniLibs/x86_64/libinstantshare.so
```



### 8.2 构建 APK

```bash
flutter pub get
flutter build apk --release --split-per-abi
```

产物目录：`build/app/outputs/flutter-apk/`（按 ABI 拆分三个 APK）。

> Release 当前使用 debug 签名（见 `android/app/build.gradle.kts`）。上架 Play 商店前需配置 release keystore。

## 十、GitHub Actions 发版 Tag

格式：`v{version}-{platform}`。同一版本的多平台 tag 会汇总到同一个 GitHub Release（`v{version}`）。


| 平台      | Tag              | 命令                                                         |
| ------- | ---------------- | ---------------------------------------------------------- |
| Windows | `v1.0.0-windows` | `git tag v1.0.0-windows && git push origin v1.0.0-windows` |
| macOS   | `v1.0.0-macos`   | `git tag v1.0.0-macos && git push origin v1.0.0-macos`     |
| Linux   | `v1.0.0-linux`   | `git tag v1.0.0-linux && git push origin v1.0.0-linux`     |
| Android | `v1.0.0-android` | `git tag v1.0.0-android && git push origin v1.0.0-android` |


手动调试：Actions → **Build Release** → Run workflow → 选分支与 platform。
